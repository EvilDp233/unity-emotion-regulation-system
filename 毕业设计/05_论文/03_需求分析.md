# 第三章 系统需求分析

## 3.1 用户需求

### 目标用户
- 在校大学生（主要群体）
- 有焦虑、压力等情绪困扰的人群
- 对心理健康管理感兴趣的用户

### 用户需求调研（建议）
- 问卷调查：情绪管理现状、工具使用习惯、功能偏好
- 访谈：对虚拟现实/交互式情绪管理工具的态度
- 文献参考：已有研究的用户需求分析结果

### 用户痛点
- 日常情绪压力缺乏释放渠道
- 专业心理咨询费用高、等待时间长
- 缺乏便捷的情绪管理工具
- 对心理健康干预有隐私顾虑

## 3.2 功能需求

### 核心功能
| 模块 | 功能描述 | 优先级 |
|------|---------|--------|
| 用户管理 | 注册、登录、信息管理 | 高 |
| 情绪评估 | 训练前后情绪自评（焦虑、压力、情绪评分） | 高 |
| 呼吸训练 | 4-7-8呼吸法引导，可视化动画 | 高 |
| 正念冥想 | 引导式冥想，计时训练 | 高 |
| 自然场景 | 森林/海边/花园沉浸式场景 | 高 |
| 音乐放松 | 放松音乐播放与控制 | 中 |
| 交互游戏 | 放松主题小游戏 | 高 |
| 数据记录 | 历史数据查询、趋势展示 | 中 |
| 系统设置 | 音效、画面等设置 | 低 |

### 功能优先级矩阵
- **必须实现**：呼吸训练、情绪评估、自然场景
- **建议实现**：正念冥想、交互游戏、数据记录
- **可选实现**：音乐放松、系统设置

## 3.3 非功能需求

### 性能需求
- 场景加载时间 ≤ 5秒
- 帧率保持 ≥ 30 FPS
- 应用启动时间 ≤ 10秒
- 内存占用 ≤ 512MB

### 可用性需求
- 操作直观，无需额外学习
- 界面美观，色彩柔和
- 交互反馈及时明确
- 符合用户心理认知习惯

### 易用性需求
- 清晰的导航引导
- 统一的交互模式
- 合理的默认设置
- 错误操作保护与提示

### 可靠性需求
- 数据自动保存
- 异常情况处理
- 运行稳定性

### 安全性需求
- 用户数据本地存储
- 隐私数据保护
- 无网络传输安全风险

## 3.4 交互需求

### 核心交互方式
- 鼠标/触屏点击
- UI按钮交互
- 拖拽交互（可选）
- 键盘快捷键（可选）

### 交互反馈
- **视觉反馈**：颜色变化、动画响应、进度提示
- **听觉反馈**：点击音效、环境音效、引导语音
- **触觉反馈**：控制器震动（VR场景可选）

### 用户体验要求
- 情绪舒缓为主色调（蓝色、绿色、暖色）
- 减少认知负荷
- 正向鼓励机制
- 个性化体验
