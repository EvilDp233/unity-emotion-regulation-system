# 答辩准备

## 高频问题与回答要点

### 技术选型类

#### Q1: 为什么选择Unity，而不是UE（虚幻引擎）？
**回答要点：**
- Unity轻量级，学习曲线平缓，适合快速原型开发
- 本项目为2.5D/轻3D场景，Unity完全满足需求
- Unity跨平台支持好（PC、移动端、WebGL）
- C#语言上手更容易，适合非游戏专业学生
- Unity Asset Store资源丰富，开发效率高
- UE更适合AAA级大作，对本次课题来说过于重型

#### Q2: 为什么不用真正的人脸识别/情绪识别？
**回答要点：**
- 本项目聚焦于**情绪调控训练**本身，而非情绪识别技术
- 人脸识别涉及隐私和伦理问题，用户接受度低
- 主观自评（情绪评分）在心理干预研究中是成熟且被广泛使用的方法
- 情绪识别可作为未来扩展方向

#### Q3: 你的创新点是什么？
**回答要点：**
- **① 多模态训练集成**：将呼吸训练、正念冥想、自然场景、互动游戏整合在同一系统中
- **② 可量化的效果评估**：通过前后测对比，数据化展示训练效果
- **③ 低成本高沉浸方案**：无需昂贵VR设备即可获得沉浸式情绪调节体验
- **④ 面向大学生的专用方案**：针对大学生心理特点和需求定制设计

### 设计类

#### Q4: 需求分析是怎么来的？
**回答要点：**
- 文献研究：参考了情绪调控干预的相关研究成果
- 用户调研：问卷调查/访谈了解目标用户需求
- 理论支撑：基于Gross情绪调节理论框架
- 竞品分析：参考了已有心理健康应用的功能设计

#### Q5: 为什么这样设计数据库？
**回答要点：**
- 采用SQLite：轻量级、无需服务器、零配置
- 表结构设计遵循第三范式
- 根据功能需求划分四个核心表
- 支持后续功能扩展（预留扩展字段）

### 系统类

#### Q6: 为什么设计这些小游戏？
**回答要点：**
- 游戏化交互能提高用户参与度和粘性
- 放松小游戏本身就是有效的注意力转移和压力缓解方式
- 符合严肃游戏（Serious Game）设计理念
- 游戏过程本身可作为情绪调节的一种手段

#### Q7: 系统有什么不足？
**回答要点：**
- 客观评价：坦诚说明不足（见论文第七章）
- 改进方向：展示清晰的后续优化规划
- 态度积极：强调这是阶段成果，具有可扩展性

#### Q8: 以后如何改进？
**回答要点：**
- 技术层面：VR兼容、情绪识别集成、AI个性化
- 内容层面：丰富场景库、增加训练方式
- 用户层面：云同步、社交功能、个性化推荐
- 验证层面：扩大样本量进行效果验证

## 答辩流程建议

### 开场（1分钟）
- 各位老师好，我的毕业设计题目是...
- 我将从以下几个方面进行汇报...

### 汇报建议时间分配（共15分钟）
| 部分 | 时间 | 内容 |
|------|------|------|
| 研究背景 | 2min | 为什么做这个系统 |
| 研究现状 | 1min | 简要概述 |
| 需求分析 | 2min | 用户需求、功能需求 |
| 系统设计 | 3min | 架构、模块、流程 |
| 系统实现 | 4min | 核心功能演示（重点！） |
| 系统测试 | 1min | 测试结果 |
| 总结展望 | 2min | 创新点、不足、展望 |

### 演示准备
- [ ] 准备录屏备份（防止现场出bug）
- [ ] 准备PPT
- [ ] 准备演示场景（确保运行流畅）
- [ ] 准备不同场景的截图备用

### 仪表与表达
- 声音洪亮、语速适中
- 与老师保持眼神交流
- 手势自然，不要背对观众
- 自信、诚实、谦虚
